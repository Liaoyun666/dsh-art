# 前端设计参考包：anim_design_brief

这个插件有 28 个工具、五个数据源。工具一多，模型在「帮我做个落地页」这种任务里
**根本想不起来去调它们**——描述里写的是「能查什么」，而模型需要的是「什么时候该查」。

`anim_design_brief` 就是为此加的入口：**一次调用**把风格、镜头、像素特效、配色与
排版预算揉成一份可以直接照着排的参考包，并且每一步都给出**下一次该调哪个工具**。

## 1. 什么时候调

任务里出现下面这些词，动手写代码 / 排版之前先调它：

- 前端：页面、网页、落地页、官网、首页、组件库、样式、CSS、Tailwind
- 界面：UI、界面、看板、仪表盘、后台、管理台、App、小程序、H5
- 游戏：HUD、血条、准心、技能栏、主菜单、结算界面
- 内容：PPT、幻灯片、海报、插画、图标、封面、Banner、宣传片
- 视觉决策：配色、配色方案、字体、排版、动效、转场、氛围

反例：纯后端接口、数据处理、写文档、修 bug —— 不用调。

## 2. 参数

| 参数 | 必填 | 说明 |
|---|---|---|
| `task` | 是 | 一句话说清要做什么，带上风格与场景线索（越具体越准） |
| `surface` | 否 | 场景，比从 `task` 猜更准：`web-landing` / `dashboard` / `app` / `game-ui` / `deck` / `promo` / `illustration`；也认中文（仪表盘、游戏 UI、海报、PPT…） |
| `mood` | 否 | 想要的感觉：克制冷灰、暖米白、胶片复古、高级、活泼、国风… |
| `palette` | 否 | 已有品牌色或指定色板，直接写进去 |
| `motion` | 否 | 动效要求：克制、只做淡入、要一点回弹、滚动驱动… |
| `limit` | 否 | 深读候选条数（3–6，缺省 3–4） |

调法：

```text
anim_design_brief(task="深色科技风的 AI 写作产品落地页")
anim_design_brief(task="数据看板，指标卡 + 折线图", surface="dashboard", mood="克制冷灰")
anim_design_brief(task="小王子主题的绘本海报", surface="illustration", palette="#1B2A4A / #F2E8D5")
```

## 3. 输出长什么样

固定五节：

1. **① 定调**：3 条最贴的风格（341 条库里选），带命中词、一句简介、适合什么，以及
   `anim_show(id="…")` 的现成调用。
2. **② 动效配方**：3–6 张镜头配方卡（124 张库里选），按场景给分类优先（落地页偏
   opening / ui-entrance / effects / typography，看板偏 data / interaction，游戏 HUD 偏
   ui-entrance / effects / interaction…），带能量与时长，以及 `anim_shot_show(id="…")`。
3. **③ 现成素材**：3–4 条像素特效（244 条库里选），要代码就 `anim_fx_show` / `anim_fx_export`。
4. **④ 配色与排版**：一套配色（6 套预设之一，或场景默认深/浅色）＋ 版式要点 ＋ 四条动效硬指标。
5. **⑤ 下一步**：按顺序列出 3–4 次调用，别一口气全读。

真实输出片段（`task="深色科技风的 AI 写作产品落地页"`）：

```text
# 前端设计参考包

- 任务：深色科技风的 AI 写作产品落地页
- 场景：网页 / 落地页（surface=web-landing）
- 用法：这是**参考**不是模板。先按下面的顺序打开 2–3 条，再动手排；参数表照抄，实现自己写。

## ① 定调：翻这 3 条风格（选 1 条当基准）

1. R6 …（命中：科技、深色）
   打开：anim_show(id="R6")；看静帧：anim_still("R6")
…
## ② 动效配方：按这个顺序排（一屏一条）

1. ui-entrance/neon-frame-forerun · 界面登场 — …
   打开：anim_shot_show(id="ui-entrance/neon-frame-forerun")；海报：anim_shot_preview(ids=["…"])
…
## ④ 配色与排版（照这个花）

- 配色方案：冷色科技（深底 + 冷光）
  #0B0D10 底　#12151A 面　#5B8CFF 主　#22D3EE 辅　#E6EDF7 字
  只让一个强调色发光：主按钮、进度、选中态；其余全灰。
- 版式：…
- 一屏 / 一页只放一个主动效，其余元素静态或只做 8–16px 位移。
- 微交互 120–200ms、页面转场 240–400ms、片头镜头 ≤ 3s；缓动首选 ease-out。
- 滚动驱动的动画必须能被 prefers-reduced-motion 关掉，且关掉后布局不塌。
- 对比度：正文 ≥ 4.5:1，大字 ≥ 3:1；焦点态用 2px outline，别只靠颜色。

## ⑤ 下一步（照这个顺序调，别一口气全读）

1. anim_show(id="R6") — 读整条风格提示词，定基调与配色。
2. anim_shot_show(id="…")；anim_shot_show(id="…") — 读参数表与「已知坑」。
3. anim_shot_preview(ids=["…"]) — 一次看几张海报，定镜头顺序。
4. anim_fx_show(id="…")，要代码就 anim_fx_export(ids=["…"]) 导到工作目录。
```

一条输出控制在 6,000 字符以内：镜头卡标题会被截断到 46 字，正文留给 `anim_shot_show`。

## 4. 从 brief 到落地的预算

**最多再深读 2–3 次，别把库全读一遍**：

| 想定的事 | 调什么 |
|---|---|
| 基调、配色、质感、成片观感 | `anim_show(id)`（341 条风格提示词，可配 `anim_still` 看静帧） |
| 动效的节奏、参数、已知坑 | `anim_shot_show(id)`；要看画面就 `anim_shot_preview` |
| 能直接跑的动画代码 | `anim_fx_show(id)`；落地用 `anim_fx_export(ids, dir)` |
| 实拍 / 绘画参考图 | `anim_ref_search(query, download=true)`（需自建素材库） |
| 手里只有一张图要拆 | `anim_extract(path)` |
| 想做视频而不是页面 | `anim_shot_*` 组 + `anim_show`，按 `docs/shots.md` 的流程走 |

## 5. 五个数据源怎么分工

| 数据源 | 规模 | brief 里负责 |
|---|---|---|
| 风格提示词 | 341 条 / 193 张静帧 | ① 定调：整体质感与配色方向 |
| 参考图库 | 8,496 张（需自建服务） | 深读阶段找实拍/绘画参考 |
| 像素特效 | 244 条 / 21 类 | ③ 现成画面：HUD、粒子、按钮反馈 |
| 镜头配方卡 | 124 张 / 10 类 / 54 海报 | ② 动效节奏：一屏一幕怎么动 |
| 元素提取 | 本机图片 | 深读阶段把参考图拆成素材与配色 |

## 6. 配色与动效硬规矩

配色按 **60 / 30 / 10**：底色 60%、面 30%、强调 10%。

| 预设 | 触发词 | 关键约束 |
|---|---|---|
| 冷色科技 | 科技 / 未来 / 赛博 / 霓虹 / 深色 / AI | 只让一个强调色发光，其余全灰 |
| 暖米白 | 温暖 / 治愈 / 柔和 | 阴影用暖灰，圆角 12–16px，动效 240–320ms |
| 胶片复古 | 复古 / 怀旧 / 胶片 | 加 3–5% 颗粒，不用纯白纯黑 |
| 黑白 + 一点金 | 高级 / 奢华 / 质感 | 强调色面积 ≤ 5%，金属感靠渐变 |
| 明亮活泼 | 活泼 / 可爱 / 年轻 | 两个亮色不等面积，动效带回弹 |
| 宣纸国风 | 中国风 / 国风 / 水墨 | 留白 ≥ 40%，主色只用于标题与印章 |

四条动效硬指标（每份 brief 都带）：一屏一个主动效；微交互 120–200ms、转场 240–400ms、
片头 ≤ 3s；滚动动画必须能被 `prefers-reduced-motion` 关掉且布局不塌；正文对比度 ≥ 4.5:1。

## 7. 它怎么选（排查「为什么给了这条」）

1. **认场景**：显式 `surface` 优先；没给才从 `task` 里匹配中文关键词，都认不出回 `generic`。
2. **拆关键词**：英文/数字整词（权重 1.5）、中文 2–3 字 n-gram（1 / 1.6）、
   再按感觉词扩展（「赛博」→ 霓虹、未来、冷光，权重 2）；停用词表剔掉「一个 / 我们」这类。
3. **打分**：风格按 id/名称/系列/简介/适用匹配；镜头卡按标题/意图/分类匹配，命中场景分类再加权；
   特效按名称/分类/场景提示词匹配。
4. **配色**：先看 `mood`/`palette`/`task` 里的触发词，其次看场景默认深浅。

给了不合适的条目，八成是任务描述太泛。补 `surface` 与 `mood` 通常立刻变准。

## 8. 让模型真的想起来调它

光有工具不够——模型不会主动去翻工具列表。插件做了两件事：

1. **描述带触发词**：28 个工具的 description 开头都写了「什么时候该用」。
2. **伴随技能**：`node tools/install.mjs` 会写一份
   `~/.agents/skills/frontend-art-reference/SKILL.md`，description 里带前端/UI/海报等触发场景，
   正文第一句就是「先 `anim_design_brief`，再按第 ⑤ 节深读 2–3 次」。
   `--status` 会报告有没有装上，`--uninstall` 只删带托管标记的那份。

验证是否生效：开一个新会话，只问「帮我做个深色风的落地页」，
看它第一步是不是调 `anim_design_brief`。没调的话，把伴随技能重装一遍
（`node tools/install.mjs`），或在会话里直接点名这个工具。

## 9. 常见坑

- **别把 brief 当模板**：它给的是参考与参数，不是 HTML。抄节奏，不抄整段代码。
- **镜头卡里的「上游实现」是 Remotion 仓库路径**，不在本机，别照着 import；要代码走 `anim_fx_export`。
- **参考图库默认没连**：`anim_ref_*` 会如实说「没连上」，不影响其余工具。
- **brief 不写文件**：要落地卡片或特效，自己调 `anim_shot_export` / `anim_fx_export` 并给 `dir`。
- **场景认错**：显式传 `surface`；它优先于从任务里猜。
