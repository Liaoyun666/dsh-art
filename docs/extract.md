# 元素提取：把一张图拆成能用的素材

`anim_extract` 处理「你手上这一张图」——前三个数据源都是现成的（341 条提示词 / 8 千张参考图 / 244 条特效），这一组是把用户自己的照片、插画、像素画、精灵表拆开：量出配色和构图，切出元素块，写出能直接粘贴的生图提示词和像素特效提示词。

纯本地 CPU，不联网，不需要 Python、ImageMagick 或任何 npm 依赖：PNG / JPEG / GIF / BMP / TGA 的解码器与全部分析算法都在本包 `lib/` 里（vendored 的 jpeg-js 与许可见 `lib/vendor/`）。

## 两个工具

| 工具 | 作用 |
|---|---|
| `anim_extract` | 分析一张图并把结果落盘：元素块、调色板、接触表、`brief.json`、`report.md`，同时在会话里回一张摘要卡 |
| `anim_extract_guide` | 就是本文件。第一次用之前读一次 |

## 它到底量了什么

| 量出来的东西 | 怎么来的 | 该不该当真 |
|---|---|---|
| 图片类型 | `scene` / `framed-artwork` / `texture` / `sprite-sheet` | 四分类是给后面的措辞用的，边界模糊时按 scene 处理 |
| 像素画倍率 | 在候选块尺寸下统计「块内相邻像素完全相同」的比例，取置信度最高的那个 | 倍率是整数才有意义；照片偶尔会被误判成 ×1（不影响结果） |
| 背景占比与背景色 | 从四条边框找种子，边缘感知 BFS 生长；强轮廓（边缘像素占比高）会挡住生长 | 占比是像素数，不是「面积观感」 |
| 天空 / 地面 / 地平线 | 背景连通块按顶边、底边覆盖率找；同一块时用逐行背景均值色的最大跳变定分界 | 渐变天空、雾、水面会偏低或偏高几个百分点 |
| 元素（bbox / 角色 / 主色 / 填充率 / 是否焦点） | 颜色量化 → 区域合并（惰性版本号 + 邻接边）→ 按亲和力与几何分组 → 小组挂到宿主 | 「角色」是启发式命名（主体 / 道具 / 文字 / 剪影 / 高光 / 小图），不是识别 |
| 构图 | 三分线命中、亮度加权重心、对称性、密度图、光向、对比度、边缘密度 | 三分线命中是「中心落在 ±9% 内」，粗判 |
| 调色板 | 像素画取精确色；照片走 median-cut，按面积加权，同一来源里色距 < 10 的合并 | 百分比是该色在画面中的占比（背景单列在最后） |
| 提示词 | 上面这些数字 + 角色表 → 英文生图提示词、像素特效规范 | 是「起手式」，不是最终稿 |

## 处理流程

~~~text
文件 → 解码头（PNG/JPEG/GIF/BMP/TGA）
     → 像素画检测（块倍率 / 是否 >1 / 唯一色数）
     → 缩到最长边 1024（像素画按整数倍缩小，保住块边界）
     → 边缘图（Sobel + Otsu）→ 颜色量化 → 区域分割（相邻区域按色差与边缘强度合并）
     → 背景：边框种子 + 边缘感知 BFS → 天空 / 地面 / 地平线
     → 元素：区域 → 亲和力分组（同色 / 同色系 / 几何邻接）→ 小组挂到宿主（attach）
     → 构图指标 + 调色板 + 提示词
     → 落盘：crops/ · palette.png · contact.png · brief.json · report.md
~~~

坐标都在「分析图」上算出，裁剪时按 `原图宽 / 分析图宽` 映射回原图，所以大图裁出来的块是清晰的。

## 四类图怎么用

| 类型 | 特点 | 建议 |
|---|---|---|
| `scene` | 有背景、有前景主体（照片、插画、游戏截图） | 主要看背景占比、地平线、主体 bbox；裁剪块可以直接当参考 |
| `framed-artwork` | 装裱过的画（四周有边框 / 纸边） | 没有可用地平线；元素会偏多，挑面积最大的几个看 |
| `texture` | 无缝贴图 | 不裁元素块（整张都是内容），只看调色板与「可平铺」判断 |
| `sprite-sheet` | 一张图里排着很多小图 | 元素≈单个小图；行列对齐要自己看接触表，工具不猜网格 |

## 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `path` | 必填 | PNG / JPEG / GIF / BMP / TGA。**WebP / HEIC 不支持**，先另存成 PNG |
| `out` | `<当前目录>/anim-extract/<图片名>/` | 输出目录，已存在会覆盖同名文件 |
| `top` | 6 | 裁几个元素块（按面积从大到小），1–24 |
| `max` | 1024 | 分析时的最长边，256–4096。越大越准也越慢 |
| `colors` | 12 | 调色板色数，2–24 |
| `cropSize` | 160 | 裁剪块目标长边，64–512；像素画会自动取整数倍放大（最近邻） |
| `crops` | true | false = 不裁元素块 |
| `palette` | true | false = 不生成 palette.png |
| `contact` | true | false = 不生成 contact.png |

## 输出

~~~text
anim-extract/<图片名>/
├── crops/00-<role>.png …   # 元素块，按面积从大到小，文件名带角色
├── palette.png             # 调色板色卡（含 hex 与占比）
├── contact.png             # 带序号的接触表，一眼看全所有裁剪块
├── brief.json              # 机器可读：类型 / 背景 / 元素 / 调色板 / 两段提示词
└── report.md               # 中文报告：表格 + 提示词 + 局限说明
~~~

接触表左下角的序号和 `crops/` 的文件名一一对应（`#0` ↔ `00-*.png`）。

## 接着做什么

- **要同类风格提示词**：把 `report.md` 里「anim_search 检索建议」那一行的中文词直接喂给 `anim_search`。
- **要参考图**：同上的英文词给 `anim_ref_search`（前提是配了参考图库）。
- **要做像素特效**：`anim_fx_search` 找最接近的现成特效，`anim_fx_export` 导出源码当骨架，再把 `fxPrompt` 里的 canvas / palette / motion 改进去。
- **要生图**：`imagePrompt` 是英文逗号分句，粘贴即可；换了模型就把「rendered as small pixel art」换成你的目标风格。

## 实测（2026-11，本机）

| 图 | 尺寸 | 类型 | 用时 |
|---|---|---|---|
| 合成场景（照片风） | 800×450 | scene，背景 78.5%，地平线 62% | ~0.4 s |
| 合成场景（像素画 ×4） | 800×452 → 200×113 | scene，倍率 ×4，23 色 | ~0.2 s |
| 精灵（透明底） | 220×300 | scene，透明背景 83% | ~0.03 s |
| 印度细密画（装裱） | 554×800 | framed-artwork，18 个元素 | ~1.0 s |
| 像素载具图集 | 480×269 | sprite-sheet，24 个小图 | ~0.2 s |
| 树木贴图 | 480×480 | texture，可平铺 | ~0.6 s |
| 欧洲油画 | 400×560 | scene，背景 16.9% | ~1.1 s |

节点侧大图（超过 1500 万像素）建议先手动缩到 2048 以内：解码是按原图解的，内存跟像素数成正比。

## 别当真的事

- **分割不是识别。** 它会告诉你「这里有一块 2.1% 画布、纵长、主色红的区域，位置在人物的位置」，不会告诉你「这是人」。角色名是规则给的（`character` / `prop` / `text` / `silhouette` / `accent` / `sprite`）。
- **元素可能被拆开或被合并。** 同一个人被树挡住就会分成两块；相邻同色物体可能并成一块。接触表就是给你肉眼纠错的。
- **地平线是「背景色突变」的产物。** 纯色背景、渐变天空、满屏特写会没有地平线或位置偏移。
- **精灵表的行列**要自己看，工具只给出每个小图的 bbox，不猜 `cols × rows`。
- **WebP / HEIC / AVIF 不解码**，会明确报错让你另存 PNG（解码器只做了 PNG/JPEG/GIF/BMP/TGA）。
- **透明通道**当背景处理：`background.transparent` 为 true 时，「背景占比」是透明像素的占比。
